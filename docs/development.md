# Development

## Prerequisites

- Go (version in `go.mod`), Node (version in `.node-version`) and pnpm.
- Docker only for building images or testing against PostgreSQL.

## Build

```bash
cd web && pnpm install && pnpm build && cd ..   # produces web/dist, embedded into the binary
go build -o bin/syncyomi .
./bin/syncyomi --config ./config                # creates config/config.toml with defaults
```

`make build` does the same. `web/dist` must exist (even just the `.gitkeep`) before any `go build`/`go test`, because `web/build.go` embeds it.

## Test

```bash
go vet ./... && go test ./...      # Go; the database tests use a temporary SQLite file, no services needed
cd web && pnpm lint && pnpm typecheck && pnpm test
```

Repository-layer tests live in `internal/database/*_test.go` and open a real SQLite database in `t.TempDir()`; handler tests in `internal/http/*_test.go` use `httptest` with a mocked service.

## Trying it end to end

1. Start the server with a scratch config directory.
2. `POST /api/auth/onboard` once, `POST /api/auth/login` with `-c cookies.txt`, then `POST /api/keys` with `{"name":"test","scopes":[]}` to get an API key.
3. Use `curl` with `X-API-Token` against `PUT`/`GET /api/sync/content` and `POST /api/sync/event`; inspect `/api/sync/admin/<key>/…` with `-b cookies.txt`.

For PostgreSQL, `docker compose up postgres` starts a matching instance on port 5434.

## Fixtures

Real Tachiyomi backups (`*.tachibk`) contain personal data and are git-ignored; keep any under `internal/backup/testdata/private/`. Checked-in fixtures must be scrubbed copies.

## Conventions

- Conventional Commits (`feat:`, `fix:`, `docs:` …). Releases and `CHANGELOG.md` are generated by release-please from the commit history, so never edit the changelog by hand.
- PR titles must be conventional too (`pr-title-lint` workflow).
